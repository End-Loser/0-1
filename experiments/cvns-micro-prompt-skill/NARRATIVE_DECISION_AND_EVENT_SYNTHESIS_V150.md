# V1.6.0 变量线关系、人物决策与事件合成规则（继承V1.5.0）

## 1. 总原则

**全覆盖检测不等于全量合成。** P09 对实体对/实体内部的已签约变量线做关系扫描，目的是不漏掉潜在交互；扫描结果必须经过 P10 分类。只有真实张力、已确认因果交互等具有叙事用途的材料，才进入后续资产或事件规划。无实质关系的线保持独立。

BASE 仍是 `entity × dimension × full valid interval` 的完整纵向轨迹，11 个维度不变。关系扫描不修改冻结变量线。当前规则下的互斥可先探索解释，再经新版本和复检形成一致计划；未解决的真实矛盾不能直接包装成悬念。

## 2. 关系类型及路由

| 类型 | 判据 | 处理 |
|---|---|---|
| `TENSION_ASSET_CANDIDATE` | 双方命题可以同时为真，但使人物目标、欲望、忠诚、资源或价值选择发生代价 | P12 评估是否形成独特故事资产 |
| `MUTUALLY_EXCLUSIVE_ERROR` | 当前已批准规则下不能同时为真，如同一时刻唯一持有者冲突 | P11A/P11B探索解释；失败/明确不探索才P11；原矛盾不得直接资产化 |
| `CAUSAL_INTERACTION_CONFIRMED` | 有源/目标节点、方向、时间先后、可说明的作用路径和证据 | P13B 可作为事件机会 driver |
| `PENDING_EVIDENCE` | 可能存在关系，但关键证据、时序或作用路径不足 | 默认挂起；宿主明确授权可探索解释，但不把解释当作证据 |
| `NO_MATERIAL_RELATION` | 仅共现、同章、同地点、主题相似或弱关联，没有可证明的戏剧/因果用途 | 终态，不制造资产或事件 |

共鸣/镜像/对仗不是因果；R-06.2 P6 实验未授权前默认关闭。

### 2.1 冲突解释不是矛盾改名

P11A为同一冲突提供不同解释和最小修复对照；P11B按原始命题、因果、边界、反例、跨线后果和叙事收益比较。通过只得到修订提案，不能绕过冻结来源。

获选解释复用P01B/P21A、P01C/P21B和P20创建新版本；变量线/规则复检后重新执行受影响P09/P10。新判定使用新扫描的canonical candidate_ref，原ref作为解释来源保留。只有新的批准张力或确认因果才进入下游。

完整执行协议见`CONFLICT_EXPLANATION_POLICY_V160.md`。候选、审读和修订manifest都是提案/门禁索引，不是新增状态线。

## 3. 人物决策模型

### 3.1 稳定倾向与动态状态分离

- P05E 是人物/决策主体级 sidecar，不是 BASE 第 12 维，也不是时间线。
- P05E 描述相对稳定的价值优先级、风险偏好、不确定性处理、信任策略、冲突/压力反应和盲点。每项需有触发条件、表现、边界/反例及证据来源；新角色的推断应标为假设，而非既成事实。
- 当下目标、欲望、信念、情绪、关系和知识仍从对应 BASE 线的事件时点快照读取。稳定倾向只影响选择偏好，不决定必然行为。
- 只给 CORE/MAJOR 或真实承担重大选择的 SUPPORTING 决策主体建卡；同一冻结版本复用。无决策责任或无下游消费者时不发模型调用。

### 3.2 P13C 对每个主要决策者分别推演

一个 EventOpportunityCluster 一次 P13C 调用，覆盖该事件内所有主要决策者；不能按人物逐个发起调用。每个人都必须区分：

1. **信息集**：当时知道什么、相信什么、误解什么、根本不知道什么。
2. **动机**：当前目标、正在起作用的欲望、价值优先级、关系责任。
3. **限制**：时间、位置、资源、能力、机制规则、外部压力。
4. **备选行动**：真正可行的选择，包括不行动/拖延/部分合作（若可行）；不能制造虚假的二选一。
5. **选择与代价**：最终选择、选择理由、放弃替代方案的原因、愿意承担的损失。
6. **一致性/变化**：选择与稳定倾向是否一致；若偏离，需有成长、认知、压力或关系变化证据。
7. **反事实敏感性**：指出最小的相关条件变化是否会改变选择；若怎么变都不改变，也要解释稳定性来源。

只有一个可行选项时，必须引用客观约束解释。若必需的人物决策倾向卡缺失，不得即兴补造人格。

## 4. 事件合成规则

### 4.1 P13B 规划的是“戏剧机会”，不是 Event

P13B 的输入是已选资产阶段与 P10 确认的因果交互。一个机会簇必须有：共同戏剧问题、共同核心行动、相互作用的决策、兼容的状态结果，以及合理时空窗口。

以下条件单独出现都不足以聚类：
- 同一章节；
- 同一地点；
- 相同主题词；
- 资产数量相近；
- 参与者名字重复。

若不同素材需要不同的核心行动、独立决策或互不兼容的状态结果，应分开。若材料没有真实行动、状态变化或受授权的读者信息变化，可以延期或明确标记本范围不发生事件。

### 4.2 资产按阶段部署

一个 StoryAsset 的 SETUP / REVEAL / PAYOFF 可以在不同事件机会中逐步兑现。每阶段严格沿用源 StoryAsset 的 `introduce_chapter` / `reveal_chapter` / `payoff_chapter`，P13B 不可重排或跨章聚类。资产阶段的读者信息上限与解禁条件不得提前泄漏。

一个事件可以同时承载多个资产阶段；同一资产的不同阶段若源目标章相同，也允许在同一事件中分别兑现，但必须证明同一个可观察行动序列能兑现各阶段且不越过 payload ceiling。不得把不同阶段合成一个模糊的“已处理”。

### 4.3 因果关系作为驱动

确认因果交互进入 P13B 时必须保留原始 `candidate_ref`，被分配到某一机会簇，或写入有原因与复核条件的未分配清单。不能因为主题相似而改写成因果驱动。每个预期状态变化必须引用当前簇内至少一个 `driver_ref`。

## 5. 从决策计划到 Event

P13C 输出的是行动意图，不是事件结果。P14A 必须让多个行动者的选择、抵抗、能力边界、资源和机制规则发生交互，再推导实际的行动与结果；不得用作者预定的反转覆盖人物最合理的选择。

P14A 只能输出源 R-06.2 `Event` 模型字段。人物决策计划、资产阶段映射和 P10 关系来源留在独立 sidecar / Artifact Envelope / 物化 manifest，不得向 Event JSON 加入 `state_deltas`、`decision_plan_refs`、`asset_deployments` 等自定义字段。

事件至少说明触发条件、参与者、各自意图、实际行动、阻力/反制、结果、代价、状态变化及其来源。决策意图不能被当成已发生的结果；计划变化不能被静默省略。无法映射到合法 Event 字段的变化应保持条件未决并阻断/报告，不得丢失。

## 6. 合成/归并验收

事件归并必须同时回答：
- 是否是同一核心行动或同一连续因果过程？
- 人物的选择是否彼此影响，而非仅仅同场出现？
- 时间、地点、规则和状态前提是否相容？
- 每个资产阶段的目标章、揭示边界和独特功能是否保留？
- 每个人物独立的选择路径、放弃方案、代价和结果是否保留？
- 每个状态变化是否有具体 driver 和源节点？

任何一项无法证明，不能仅为减少事件数量而合并。P14C0 还必须保证 BASE 状态变化节点在本章只有一个事件所有者；不能唯一归属时阻断。

## 7. 可验证性边界

代码/schema 可以验证字段、引用、阶段章、唯一性、状态、依赖和来源链；LLM/独立读者仍需判断因果解释是否可信、人物选择是否有说服力、事件是否有戏剧力量。静态结构通过不等于人物“活了”，更不等于小说达到出版级质量。V1.5.0 必须通过真实模型的连续章节 A/B 和独立盲读继续验证。
