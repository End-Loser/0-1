# 已知问题与限制（v1.7.0）

> 本文件只记录问题、限制和待验证事项；**不包含测试小说正文、样章、修订候选或样本输出**。历史测试的数据流分析报告不含小说正文，见 `case_studies/`。

## 1. 高优先级问题

| 问题 | 影响 | 当前状态 | 下一步 |
|---|---|---|---|
| 宿主调度器未随包提供 | 没有宿主就无法完成会话隔离、输入包拼接、权限、审批、冻结和索引激活；“Skill 能读”不等于“流程能跑” | 已知，未解决 | 实现宿主适配器；给出最小可运行 demo；记录权限/会话/冻结边界 |
| 文学质量未验证 | 静态测试只验证结构、预算、契约和回归，不证明人物、因果、文风、节奏或读者体验 | 已知，未验证 | 做同大纲/同模型/同预算的对照实验；人工盲评；多题材复现 |
| 历史实测样本很小 | V1.4.1 历史归档只有 73 份输出、0 个正式批准章节；没有与简单长提示的对照基线 | 已知 | 重新做 ≥2 部不同题材/长度的对照实验；预注册指标 |

| 模型依赖 | 实际模型、tokenizer、费用、上下文窗口和输出质量随 provider/model 变化 | 已知 | 在目标模型上重跑；记录模型版本/参数；不要跨模型外推 |

## 3. 历史实测记录的边界

项目 README 与 `case_studies/TR-20261104_MULTILINE_DATAFLOW_USAGE_REPORT.md` 记录了一次 **V1.4.1 历史归档**的小规模数据流实测（不含小说正文）：

- 73 份模型输出，60 份（82.2%）有下游 ID 引用；
- 5 份（6.8%）为可避免调用：3 次重复 P04B、1 次空 P05C、1 次无批准 VoiceCard 的 P19F；
- 正式批准章节 **0**，只有一份约 4,628 汉字的 P18 诊断草稿；
- 成本记录：子代理 ¥23.27 + 主会话 ¥7.34 = API 合计 ¥30.61；
- 这不是完整小说生成成本，也不是 v1.7.0 的文学质量证明；
- 本归档不包含该测试的小说正文、样章、修订候选或样本输出，因此不能只靠本包复现这次测试的全部输入。

## 4. 设计层面未解决的问题

1. **“高质量小说”如何定义和测量**：人物一致性、因果、节奏、文风、读者情绪、商业可读性，哪些可以自动评估，哪些必须人工盲评？
2. **流程复杂度是否值得**：更多调用、更多 schema、更多审批，是否会在真实项目中抵消收益？
3. **变量线 vs 章节摘要的边界**：哪些信息必须放进变量线，哪些可以按需投影？长上下文和成本如何平衡？
4. **解释优先的冲突处理**：每个互斥都先解释，是否会导致流程过长？何时应直接修订规则？
5. **可编程性与可审计性的取舍**：越结构化越可查，但也可能压扁创作直觉。

## 5. 工具与测试边界

- 工具与测试**未在本归档中重新执行**；需要在本地安装 `requirements-dev.txt` 后重跑。
- `tools/real_novel_test.py` 需要宿主提供 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_PRIMARY_MODEL`，并指向已有完整前置证据；本包不含密钥或宿主。
- 测试中的 `test-only` / `not-a-real-key` 是占位符，不是真实凭据。
- 测试通过只代表结构/契约/回归通过，不代表文学质量或真实小说可用。
- 样章专用工具/测试（18 个工具、19 个测试）未包含；`tools/real_novel_test.py` 与 `tools/writer_length_contract.py` 保留为测试/契约代码，但需要外部样章证据才能走完整路径。

## 7. 建议的下一步

1. 实现一个最小宿主适配器（会话隔离、输入包、审批、冻结、索引）。
2. 用合法、可公开的样本做对照实验：本流程 vs 简单长提示；预注册指标。
3. 补 P01E/P01F 的 Schema 缺口与宿主批准流程。
4. 实测输入包大小/token 成本，验证 150/200/300 KiB 阈值是否合理。
5. 记录失败案例：被拒绝的解释、被延期的事件、BLOCKED 的章节、质量下降的样本。
6. 在至少两部不同题材/长度的小说上复现，避免单样本结论。
