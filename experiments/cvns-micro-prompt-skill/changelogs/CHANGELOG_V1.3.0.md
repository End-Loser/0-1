# Changelog V1.3.0

## 核心目标
把上一版“任务已分类”进一步优化为真正的微任务执行提示词：一次调用只承担一个自然认知任务，通常1–2项、最多3项语义限制；生成、审计、修复、批准严格分开。

## 主要变更
- 清除模型可见提示词中的 `predecessor`、`validators`、调度命令和下游验收指令；这些信息仅保留在 TASK_REGISTRY 和宿主说明。
- 移除提示词 YAML/调度元数据重复，任务正文统一为唯一目标、最小输入、1–3项相关限制、单一输出。
- 将 POV 归属、人物知识、物品流转、身体/存在、场馆位置拆为独立审计提示词。
- BASE 维度注册表去掉与提示词重复的语义描述，每次只注入当前维度紧凑状态格式行。
- BASE 实际调用负担固定为公共核心2项 + 维度专属1项；仍保持一条完整 entity×dimension 轨迹一次调用。
- 修正 P18 Writer 注册表的限制计数，使其与实际提示词的三项限制一致。
- 补强机制规则合同：layering 与 contact_semantics 必须明确声明适用或不适用，不能默默遗漏。
- 增强静态校验：提示词正文限制计数与注册表一致、最长700字符、没有路由元数据泄漏、输出合同引用有效。

## 保留的 R-06.2 自然任务例外
- P06：一次全局 ExpressionTaskbook 矩阵规划；不按维度拆分。
- P09：一次实体对全部维度冲突扫描；不按维度过滤或有损截断。
- BASE：一次 entity×dimension 完整有效区间轨迹；不按章节或状态字段切碎。

## 未解决的宿主/运行时事项
- 文件冻结与禁止覆盖必须由宿主调度器/文件系统权限执行；提示词只能表达操作合同。
- R-06.2 当前 Python 运行时与 v7.6 设计书存在偏差，详见 RUNTIME_ALIGNMENT_R062.md；本 Skill 不修改 Python 项目。
- 本版静态检查不证明任一模型一定遵守提示词，也不证明生成小说的文学质量。
