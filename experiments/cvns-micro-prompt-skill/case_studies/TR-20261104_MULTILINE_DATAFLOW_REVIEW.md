## 3. 主要数据浪费/返工原因

1. **候选资产未经组合去重**：P12逐条决定创建，P13全部接收，缺少资产组合边际价值审查。
2. **一资产一事件**：5条资产共享同一章、同一时空、同一参与者和同一登记动作，P14A生成5个近重复事件。
3. **缺少事件机会层**：资产无法先按可能由同一事件承载的方式聚类。
4. **缺少事件节点唯一所有权处理**：P14C发现多个 Event 同时声称同一 BASE 变化节点，并形成循环依赖，但上游没有归并步骤。
5. **工作流依赖顺序错误**：P08 在 P14C 前执行，读到5个候选，P14C后来只放行3个，P15A因此报 D-09。P08 应在最终事件序列之后运行。
6. **没有章节计划批准/冻结步骤**：P14C/P15A/P15B 保持 DRAFT 且存在 placeholder ID，P17C即使内容完整也无法变 READY。
7. **Writer输入包依赖闭包不完整且重复**：P17C V1缺 WC全文，V2仍缺 EntityRegistry/purpose/secrets、资产manifest、部分审批证据；按 domain 过滤还漏掉实际引用的 WC-02。输入包过大且重复加载。
8. **生产与诊断 Writer 混用**：P17C BLOCKED 后仍用生产 P18 强制写草稿；应分为生产 P18 与 P18D 诊断渲染。
9. **空输入仍调用模型**：P05C无语言样本仍调用，产生空卡，后续 P19F也失去基线。
10. **审计任务输入不匹配**：P19D无正文输入却被描述为正文因果审计，应拆分设计层 P19D 与正文层 P19D2。

## 4. 本轮使用/排除的严格结论

- 不把“未进入正文”全部等同“丢弃”：审计、提案、阻断和诊断成果本来就不应进入正文。
- P12 的5条资产全部被下游引用；未发生资产物理丢弃，但缺少组合筛选，导致事件层冗余。
- P14A 的5个事件中2个被证据门禁排除，3个进入排序；最终3个也未形成可批准总序，因此本章没有正式可交付事件序列。
- P18正文只有1份，作为诊断草稿被审计使用；正式可交付章节为0。
- 本次所有原始输出均保留；“未采用/被阻断/被取代”是流程状态，不是删除文件。

## 5. V1.4.0 对应修复

- P12 增加资产边际价值和拒绝条件；P12B 做同范围资产组合筛选。
- P13 仅接收 SELECTED 资产；P13B 对资产聚类成事件机会组。
- P14A 改为一机会组一事件；P14C0 增加事件去重与 BASE 节点唯一归属；P14C 只排序无阻断事件。
- P17A 使用固定决策枚举并在 P14C 前运行；P08 调整到 P14C 之后。
- 新增确定性章节计划批准/稳定ID/冻结脚本；P17C 要求完整依赖闭包。
- P18 只负责生产；P18D 专用于诊断草稿。
- 缺少语言样本时跳过 P05C/P19F；P19D2 单独审正文中的事件呈现。
- 输入包按引用闭包构造，去重并记录每项注入的理由和消费者。
