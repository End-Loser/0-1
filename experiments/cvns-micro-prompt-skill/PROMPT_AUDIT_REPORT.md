# 提示词与数据流审计 V1.5.0

本版本的数据流修复依据来自 `TR-20261104-MULTILINE`。必须区分不同计量口径：`call_log.csv` 有 73 条记录；子代理实际为 74 个会话（其中 1 次 P07C 重试未写入 call_log）；归档中有 74 个 JSON 输出文件（73 份模型输出 + 1 份 P19B `NOT_APPLICABLE` 确定性记录）；输入包 73 份；冻结副本 22 份。会话数、日志行数、输出文件数不是一一对应的同一指标。

重点修复：
- 5 次明确可避免调用（3 次对已注册实体重复 P04B；1 次无语言样本 P05C 空 VoiceCard；1 次无批准 VoiceCard 仍执行 P19F）。
- P19F无批准VoiceCard时前置条件不成立，应在调用前SKIP；该次计入5次明确可避免调用。
- 完整Writer Pack在P17C/P18/独立文件三处重复，已增加P17C manifest-only和P18 single-pack要求。
- 5条资产被一资产一事件机械展开，产生同质事件；增加P12B资产组合筛选、P13B机会聚类、P14C0节点归属。
- 5个EventCandidate均被审查，但0个成为批准事件序列；不能把“审查后未晋级”误计为未使用或文件删除。
- P17C BLOCKED后正式P18不得执行；诊断输出必须走P18D。
- P09/P10 不能把共现或主题相似误报为因果；因果候选需有源/目标节点、时间先后、作用路径和证据，P10 确认后才能作为 P13B driver。
- P13C 将一个机会簇内的主要决策者作为同一事件决策场景推演，逐人保留信息集、动机、可行选项、选择、放弃理由、代价和反事实敏感性；人物稳定倾向卡不是新增 BASE 维度。
- P14A 的 Event 只允许使用 R-06.2 原始 Event 字段；决策计划和资产阶段通过 Artifact Envelope/manifest 保留引用，不向 Event 添加自定义字段。

数据消费分类和具体数量见 `case_studies/TR-20261104_MULTILINE_DATAFLOW_USAGE_REPORT.md`。

本报告是工具和流程修复依据，不表示新 Skill 已通过下一轮真实 LLM 质量测试。

## V1.5.0 本轮补强与当前合同
- P09 由“冲突扫描”扩展为关系候选扫描：冲突候选与定向因果交互候选并列，但不把共现/主题相似当作因果。
- P10 的调用单位改为单条关系候选；结果分流到 P11/P12/P13B 或显式无实质关系终态。
- P13B 从资产计数转向戏剧机会聚类，资产按 SETUP/REVEAL/PAYOFF 分阶段部署；一个簇可由资产阶段和/或确认因果交互驱动。
- 每项预期状态变化必须指向簇内具体 driver_ref，防止事件规划写出无来源的“状态变化”。
- P13C 在每个事件机会簇内一次性推演所有主要决策者；P14A 再根据相互行动生成事件结果，不能把单个人物意图直接当成事件结果。
- P05E 只记录稳定决策倾向，不取代 11 条 BASE 线中的动态目标、欲望、认知、关系等状态。

这些是 Skill 规格和工具层的增量修订。除静态与单元测试外，尚未用真实模型完成 V1.5.0 端到端小说质量验证。

- 发现并修复 P14A/P14C0 对旧 `state_deltas` 草图字段的引用；现以 `EVENT_MODEL_SCHEMA.json` 的 `variable_changes`、`causal_links` 等真实 Event 字段为准。P15A 接收 READER_COGNITION 揭示义务并映射到 OutlineBeat payload，避免与人物知识变化混淆。
