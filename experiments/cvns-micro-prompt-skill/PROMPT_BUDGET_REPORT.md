# 提示词与输入数据预算报告 V1.7.0

## 提示词正文预算
- 每份模型提示词正文默认≤700字符目标；`tools/validate_skill.py` 静态上限3000字符（最长 P26=2529、次长 P18=2035）。
- 每次调用语义限制默认1–3项，硬上限15项（长任务）；任务注册表记录限制数量。
- BASE 实际为 BASE_LINE_CORE 两项 + 当前维度规则（1–5项）。
- P06、P09、P12B、P13B、P14C0 是自然组合任务，不按输入行数或输出条数判为多任务。
- validators、predecessors、权限和下游任务说明只留宿主注册表，不注入模型正文。

## 输入数据预算（与 prompt 字符数分开）
- 默认150 KiB预警、200 KiB复核、300 KiB以上需例外审批。tokenizer可用时以token数为准，否则使用UTF-8字节做代理并标记 `bytes_proxy`。
- 同一输入包中同一 artifact/version 只允许完整物化一次；其他位置引用字段或ID。
- P17C只读取依赖闭包、版本、审批和hash回执；不加载完整Writer Pack。
- P18完整Writer Pack只出现一次，不能同时顶层复制chapter_outline。
- 事件单元检查只传目标事件和必要状态切片；每个审计只传它所需的数据投影。

## TR-20261104-MULTILINE实测
- 73个输入包合计4.326 MiB；4份超过200 KiB，其中3份超过300 KiB。
- 检测到76组重复JSON子树；其中完整约340 KiB Writer Pack在P17C、P18和独立文件中重复三次，属于明确需要修复的装包问题。
- 另有事件、资产、章节大纲和BASE节点重复；其中部分是独立会话所必需，但必须按任务投影，而不是全量复制。
- 该测试输入包预算审计见 `case_studies/TR-20261104_MULTILINE_input_pack_efficiency.json`。

## 边界
字节量不等于token数；重复子树存在嵌套，不能直接相加宣称节省量。静态预算通过不证明LLM会正确使用上下文。

## V1.5.0 本轮实测静态预算
- V1.5.0 历史扫描：77 个注册任务、78 个提示词文件；每任务最多 3 条语义限制；11 条 BASE 维度；提示词最长 544 字符。
- 调用数量约束：P05E 每个重要决策主体一次，VALIDATED/FROZEN 后按版本复用；P13C 每个事件机会簇一次覆盖全部主要决策者，不按角色逐人调用；无决策主体由宿主生成终态，不发模型调用。P10 仍按单条有实质候选调用，弱/无实质关系不得送入。
- 本轮新增决策推演调用，因此不能宣称 V1.5.0 成本低于 V1.4.1；需用真实 usage 做对照。静态预算不证明实际 Token 成本。

## V1.6.0 当前静态预算
- 79 个注册任务、80 个提示词文件，11维；主动限制最多3项、平均2.13项；实测来源绑定修复后提示词最长588字符。
- P11A/P11B 分别对一个冲突调用一次；不按候选数量追加调用。普通错误允许只有最小修复候选，不凑反转或机制配额。
- 冻结包和激活元数据只留宿主，不增加 Writer 的候选长报告上下文。本轮未测真实模型费用，不声称节省 Token 或生成成本。
