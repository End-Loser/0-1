# 微任务提示词设计标准 V1.7.0

## 调用单位
一次调用执行一个自然认知任务，不是一个孤立字段。允许输入/输出多项数据，只要它们共同服务于一个决策目的。BASE 是一个 entity×dimension 完整轨迹；P06 是全局矩阵；P09 是一对实体全部已签约线；P12B/P13B/P14C0 分别处理一个范围内的资产/事件组合。

## 语义限制预算
每个生成类提示词默认 1–3 项；长任务（P18 长章写作、P26 长篇压力测试等）硬上限 15 项，且每项仍须服务同一个自然任务。不要把多个任务藏在输入或交付描述中。纯字段/ID/日期/数值约束交程序；语义判断由对应专项提示词处理。

## 生成与审计
生成提示词只生成；审计提示词只审计；修订提示词只根据一个已确认问题产生新版本；批准/冻结由确定性宿主处理。

## 数据消费
每个任务输出必须有明确下游消费者，或明确标为终端审计/提案/诊断。无消费者的任务不得默认执行。NO_ASSET、NO_EVENT、DEFERRED、NOT_APPLICABLE 是合法结果。

## 输入最小化
按引用依赖闭包装包；精确加载所引用的 WorldConstants ID；同一文件/记录不得在一个输入包重复出现。记录每个输入项的纳入理由和 hash。

## 版本保护
每个任务只写自己的新成果路径。FROZEN 不覆盖。返修创建新版本并执行影响分析。


## V1.5.0 新增原则
- 稳定人格/组织决策倾向采用 `P05E` sidecar，不增加 BASE 维度；临时状态仍属于现有变量线。
- 关系扫描区分“张力”“互斥”“有方向证据的因果交互”。不把同章共现、主题相似或心理矛盾直接判为因果。
- 资产组合与事件部署分离：P12B 决定资产价值；P13B 决定资产各阶段在哪些事件机会中兑现。一个资产可跨多个事件按 SETUP/REVEAL/PAYOFF 部署。
- P13C 以一个事件机会组为调用单位，输出所有主要参与者各自的选择逻辑；不可为每个参与者追加独立调用。
- 事件合成只发生在人物选择相互作用并导致行动/状态或读者信息变化时；事件数量不由资产数量、冲突数量或章节节拍数量决定。

## V1.6.0 解释与事实分离
- P11A 只提解释候选，P11B 只比较合理性与收益，不合并成“生成且自证通过”的任务。
- 候选须覆盖全部原始命题，提供最小修复对照；解释可异类，但不能靠无限例外逃避规则与跨线检验。
- 结构检查、语义审读、宿主批准、新版本物化及索引激活分别执行；Writer 只能渲染批准的一致计划。

## V1.7.0 长篇压力测试与成长/战斗提案
- 新增 P01E 修炼体系提案与 P01F 战斗规则提案：两者只产出 PROPOSAL，须经 P21A 单规则修订与宿主批准后才可映射为 WorldConstants；未批准前不得被 BASE_POWER 当作既定等级使用。
- 成长体系必须给出资源循环（来源/转化/归还或消耗/过量后果）与伤势粒度；战斗规则必须给出能力边界、行动链、多类胜利条件与越级代价。只列境界名或招式名不算机制。
- 新增 P05F 叙述声音指南：只作为既有写作说明注入 Writer，不得修改任何 Schema 或 BASE 结构。
- 新增 P26 长篇压力测试 sidecar：冻结基线 + 逐章状态提交 + 滚动审查 + 回归账本；它不替代正式 Canon、审计回执或依赖闭包清单。
- 提示词静态预算放宽为最长 3000 字符、最多 15 项限制；仍保持“一任务一调用”与生成/审计/批准分离。
