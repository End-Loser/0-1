## 原文

```text
最初思想：
问题1：大模型有最大窗口限制
问题2：长篇小说需要处理各种上下文传参

长篇小说中，纵向观看一个变量的变化，这个变量可以是人，也可以是一个宝物，功法等等。我们纵向拆分整个小说成原子变量。大模型可以一次生成这个变量的所有数据，比如2000章中小说该变量的所有变化。这些变化组成了改变量实体的变量线，把所有变量都生成就组成了整个长篇小说。如果说变量线之间有冲突，让这些冲突变成小说的设计资源，金手指，新颖情节，伏笔等等。好的小说是非常合理的，再离谱的小说能解释通就可以变成小说的营养设定。难点在于1.变量线生成却生成不了好的小说。2.变量线之间处理问题。也有其他一些问题，还需要深入分析。
```

## 要点

- 大模型有最大窗口限制；长篇小说需要处理各种上下文传参。
- 把小说**纵向拆成原子变量**（人、宝物、功法等），每个变量生成跨全部章节的完整变化，形成变量线；所有变量线组合起来就是整本小说。
- 变量线之间的冲突可以转化为**小说的设计资源**：金手指、新颖情节、伏笔等。
- 好小说是“合理”的；再离谱的设定，只要能解释通，也可以成为小说的营养设定。
- 核心难点：变量线生成不一定能生成好小说；变量线之间的处理仍需深入分析。

## 与后续设计的关系

后续设计书把这一原始想法展开为：变量线 = 完整状态机 = 全部上下文、冲突检测与解释、事件合成、Writer 渲染、宿主审批/冻结等流程。
