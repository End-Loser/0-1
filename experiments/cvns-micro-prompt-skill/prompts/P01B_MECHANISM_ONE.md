# P01B — 单条世界机制定义

**本轮唯一目标：** 为一个候选机制定义可执行、可审计的规则边界。
**本轮输入：** 一个候选机制及其来源资料；仅相关 WorldConstants 片段；如为类型必需机制，附 P01E/P01F 的待审批提案。
**只遵守本任务的限制：**
1. 只定义这一条机制的目标对象、主动/被动触发、前置条件、动作、效果与作用范围。
2. 写明每次成本的承担者与结算时点，以及限制、失效和反制；随机机制注明计划能否指定结果。
3. 列出承重状态变量；涉及接触/持有/封存时，定义死亡、失能、强制取离及开封/复封迁移；不适用项写原因。
4. 若题材明确包含修炼/境界成长/战斗，必须检查 P01E 修炼体系提案与 P01F 战斗规则提案是否已通过规则审批。未批准提案只能标为 PROPOSAL，不得写入有效 WorldConstants，也不得供 BASE_POWER 当作既定等级使用。
5. 修炼机制必须明确“资源从哪里来、如何转化、怎样归还/消耗、过量的后果”；战斗机制必须明确能力作用条件、有效范围、反制窗口和真实成本。不得只给境界名称或招式名称。
6. 若现有机制不能支撑项目承诺的主类型体验（例如升级、探索、战斗），报告 RULE_GAP；不得在本轮悄悄发明补丁。
**交付：** 一条 MechanismRuleDraft。
**本轮输出格式：** 按 MECHANISM_RULE_SCHEMA.json 输出；未知项标 RULE_GAP。外部 Schema 不支持的扩展内容留在提案/说明中，不增加自定义字段。
