# P15A — 单章节拍图

**本轮唯一目标：** 把本章已确认事件编排为具有阅读推进、场景转折和情绪节奏的 ChapterOutline 节拍。
**输入：** 本章事件序列（含 causal_links）、相关变量线快照、NarrativeLens、场馆及揭示解禁条件、相邻章节接口和可用 ReaderEmotionCurve 摘要。
**只遵守本任务的限制：**
1. 只分配节拍、POV、在场实体和场馆；不得新增或改写事件，不得改变因果事实、结果、人物选择或已批准的信息揭示边界。
2. 每拍引用相关事件/变量线；跨场馆行程按拍声明场馆，不遗漏 location 线。
3. `READER_COGNITION` 因果链接映射为获准 beat 的 payload/required_elements；不得写成人物 knowledge_changes 或提前揭示。
4. 在不改变事件事实的前提下，安排读者注意力：明确本拍的即时目标/问题、主要阻力或信息变化、拍末状态/悬念；并标识必要的停顿、缓冲或情绪释放。不要让每一拍都以冲突、惊吓或反转收尾。
5. 同一事件可按其真实行动过程拆成多个节拍，但不得把同一动作重复包装成多个事件；场景转折必须由新行动、新信息、选择或后果触发。
6. 允许在节拍呈现层采用冷开场、回溯、交错 POV 或延迟揭示，但必须保持事件真实时间戳和因果关系可追踪；读者获知顺序不得被冒充为事件发生顺序。若现有 ChapterOutline 合同没有独立字段，使用既有 beat 的说明/payload 记录，不得添加自定义字段。
7. 检查本章是否只有“发生了什么”而缺少“读者为什么在意”。同时检查本章是否只有主角在行动、配角只提供信息；若配角有独立目标，必须保留其可观察的行动或选择。
8. 若主类型包含修炼/战斗，本章节拍必须明确能力使用的前置、战术目标、空间关系、反制窗口和代价承载位置；不得仅写“交手/爆发/大战”。
**输出：** ChapterOutline；beat_id 由代码发放，不手写最终 ID。
