# P01E — 修炼体系与境界成长提案

**适用条件：** ProjectContract 的主类型包含修仙、玄幻成长或明确的力量等级推进。
**本轮唯一目标：** 设计一套能够支撑长期人物成长、探索和冲突的修炼体系提案；不直接写入已生效 WorldConstants。
**输入：** ProjectContract、ThemeSpec、现有 WorldConstants、世界机制候选、目标篇幅/章节密度、主要人物叙事需求。
**只遵守本任务的限制：**
1. 先定义力量资源来源、获取方式、转化路径、储存/释放、归还/耗散和不可逆成本。不得只起境界名称。
2. 境界建议通常为 4–7 个宏观阶段；每阶段写清：核心能力变化、可执行行动、绝对不能做什么、突破前置、突破过程、失败后果、维持成本、被何种策略反制。阶段之间必须有质变，不可只是数值增大。
3. 境界、技能熟练度、知识、法器/资源和战术位置分开建模。低境界角色可用地形、准备、合作、信息和规则争取局部目标，但不能无成本正面压倒高境界角色。
4. 晋级不得按章节或卷数自动配额。为每位主要人物定义成长需求时，说明其与欲望、缺陷、代价和主题的联系；有些人物可以停滞、拒绝晋级、走偏或失去能力。
5. 设计至少三类成长路径：常规修炼、实践/探索所得、代价或失败后的适应。若世界规则只允许其中一类，明确说明。
6. 设计资源稀缺、师承/制度/宗门/地缘如何影响修炼机会；不让世界只服务主角，配角和对手也必须受同一规则约束。
7. 对常见“战斗后自动突破”“顿悟即全能”“丹药无成本升级”“越级胜利无代价”等套路进行规则层限制。
8. 伤势必须按身体结构粒度记录：主脉/细支脉、感知功能/导流功能、暂时失能/永久损伤分别描述；若某一功能仍可部分使用，必须写清触发条件、强度、持续时间与反噬边界，禁止把“局部损伤”笼统写成整条能力全失或无影响。
9. 输出应标记 SOURCE_FACT / INFERENCE / PROPOSAL / RULE_GAP。与现有规则冲突时提出冲突，不自行覆盖旧规则。
10. 本提案须经 P21A 单条规则修订/项目审批流程后，才可映射到既有 `WorldConstants.power_ladder`。若外部 Schema 或注册表不支持所需信息，标 `BLOCKED_SCHEMA_GAP`，不得擅自增加字段或冒充批准。
**交付：** CultivationSystemProposal（提案，不是正式 WorldConstants）。
