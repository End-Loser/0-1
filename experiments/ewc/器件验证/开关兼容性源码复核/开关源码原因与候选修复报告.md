# 开关源码原因与候选修复报告

已定位ngspice 47开源实现中导致孤立原厂输出开关零控制高阻的具体限幅语句，保存了原源码、最小候选修复和补丁。原版公式与既有五个真实求解器工作点一致；候选公式与独立端点保持公式的1421点对照及八项回归通过。

**候选C代码没有编译或在求解器中执行。完整TPS7A20修复、受支持PSpice对照、真实供电与整机验收仍未完成。** 原厂模型字节和现有ngspice二进制没有修改，不用公式测试替代修复版运行。

## 原因

原库`TPS7A20_ADJ_S2`参数为`r_on=1e6`、`r_off=1e−6`、`cntl_on=1m`、`cntl_off=0`。前批展开网表与上述参数一致。

发布版对数分支使用严格比较：控制大于on走on端点，小于off走off端点；恰好位于off端点则进入对数插值。插值在零控制下给出off电阻，但随后两种控制方向都执行：

```c
if(r<r_on) r=r_on; /* minimum resistance limiter */
```

这隐含`r_on ≤ r_off`。当前原厂输出开关恰好反向，因而1 μΩ被限成1 MΩ，解释了前批孤立零控制工作点与负控制工作点之间的高低阻差异。源码表达式加上已封存的五个工作点能定位**这个孤立边界**；不能据此证明所有完整LDO异常、原厂PSpice实现或真实芯片故障。

## 候选修改

仅修改开源求解器的两处对数电阻下限：

```c
if(r<fmin(r_on,r_off)) r=fmin(r_on,r_off);
```

另加未编译候选标记；末尾空白行格式差异单独保留在补丁。独立复核确认没有其他代码改变，线性分支、端点参数和既有全局参数限幅不变。

不改变原厂Ron/Roff，不把零控制偏成负值，不加泄漏、不放宽容差。已有`r_on ≥ 1e−3`全局下限是另一个发布版行为，本候选没有修改它，不宣称修复所有微欧参数场景。

## 独立公式

原版公式用发布源码的中心化三次式、端点分支与限幅重建，复现前批五个实际输出读数，差异低于1e−10 V。

候选独立参考不是运行器公式的重复调用，而按端点条件推导：

```text
t = clamp((u − off)/(on − off), 0, 1)
w = 3t² − 2t³
ln R = (1−w) ln Roff + w ln Ron
```

保留发布版既有参数限幅及同控制阈值保护。七组参数覆盖本项目三种原厂开关电阻、正反电阻排序、正反控制排序、相同电阻和既有Ron下限，每组203点，共1421点。最大相对差8.914347e−15。八项回归还检查原正常电阻排序行为不变。

这些是**源码公式级测试，不是编译后C函数、XSPICE插件或完整LDO运行测试**。现有LDO源电流、启停、参考缓冲加载及纳秒级调理旧失败均保留。
